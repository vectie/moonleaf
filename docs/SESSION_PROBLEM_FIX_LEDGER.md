# DocumentSession milestone: problem/fix ledger

This ledger records the independently verified viewer/simple-editor milestone.

| Problem | Implemented fix | Verification |
|---|---|---|
| Callers need an editing lifecycle beyond `open`. | Added opaque `DocumentSession`, format capabilities, transactional edits, conservative dirty tracking, and verified save-as-copy. | Public black-box session tests are run separately on all four targets (`wasm`, `wasm-gc`, `js`, and `native`), and focused regressions are run directly because aggregate `all` missed one failure. |
| Failed edits could expose partial state. | Build, rerender, and normalize a candidate before committing it. | Failed-edit tests compare revision, dirty state, scene, diagnostics, and serialized package bytes with the pre-edit session. |
| Mutable results could alias session-owned state. | `scene()`, `diagnostics()`, and `VerifiedDocumentCopy::bytes()` return defensive copies. | Tests mutate nested scene arrays, push an entry onto a returned diagnostics array, and mutate returned verified-copy bytes, then reread and compare session-owned values; they do not mutate nested diagnostic data. |
| Public struct fields were externally readable and allowed callers to bypass defensive accessors. | Every field of `DocumentSession` and `VerifiedDocumentCopy` is now `priv`. | Generated `.mbti` shows only private fields while public methods remain. Black-box callers can no longer directly reach the `source_archive`, `scene`, `diagnostics`, or `bytes` fields. |
| Package ownership could be overstated. | Keep the copy guarantee at the session boundary only. `@opc` `Package` and `Part` are public mutable values, so `Package::part` is not documented as returning a defensive copy. | API/source review and black-box mutation tests for the three session-owned accessors above. |
| No-op and dirty semantics were unclear. | Semantic no-ops preserve revision and dirty state; successful edits increment revision. When `find == replacement`, `DocumentSession` returns `self` after capability/format validation and before low-level DOCX/PPTX editor dispatch, preventing a low-level rewrite from canonicalizing entity-coded XML despite semantic identity. XLSX `replace_text` remains unsupported even when `find == replacement`. Dirty is conservative: edit-away/edit-back remains dirty until save because undo and baseline-equivalence detection are not implemented. | The PPTX regression uses entity-coded `A&#66;`, which renders as `AB`, and proves revision 0, clean state, unchanged scene, and exact slide XML bytes after save. |
| Save could silently lose package content. | Serialize, reopen, rerender, and verify exact OPC part-name/payload equality before returning a clean copy. | Synthetic in-memory fixtures preserve root relationships, nested part relationships, custom XML, and binary media sentinels; DOCX additionally verifies exact unknown-part save preservation. This does not claim per-format sentinel save coverage. ZIP metadata and edited-XML lexical identity are not generally promised. |
| Root behavior needed realistic format parity. | Exercise unified root open/session behavior with synthetic, in-memory, minimally realistic/real-world-shaped DOCX, XLSX, and PPTX OOXML packages. These are not checked-in real Office files. | Root parity covers all three formats. Fixtures include root and nested part relationships, custom XML, and binary media sentinels, without claiming entities/comments/CDATA coverage. Malformed root coverage is DOCX; no cross-format malformed or warning-bearing unified-fixture claim is made. |
| Spreadsheet and text edits need conservative rejection. | Reject empty searches, operation/format mismatches, formula-cell edits, and non-anchor merged-cell edits; validate sheet and cell coordinates. | Positive, negative, no-op, and capability tests on all targets. |
| Archive safety needed an accurate dependency baseline. | The vendored `hustcer/fzip` 0.8.5 decoder applies fixed coarse defaults: maximum input 1 GiB, total output 100 MiB, per-entry output 100 MiB, 100,000 entries, and deflate ratio 1000, with filename/extra-field and central-directory validation. `unzip_sync` validates central-directory sizes before entry allocation. CRC verification exists but defaults off. | Local dependency source review. Residual release work is MoonLeaf-owned configurable stricter per-open policy, stress tests, and an enabled/verified CRC/integrity policy—not adding limits from zero. |

## Verification

The independently run milestone gate passes **93/93 tests on each of wasm, wasm-gc, JavaScript, and native** (372 target-test executions), together with `moon info`, `moon fmt`, `moon check --target all --warn-list +73`, and `git diff --check`.

## MoonCode/controller problem and fix record

Observed failures included a failed turn after a valid source edit; `Part.content` mistaken for a method together with a missing `Option` unwrap; a wrong fixture-source assumption that looked for `AB` although the fixture contained `Hello slide`; an aggregate `moon test --target all` run that did not expose the focused failing regression, leading to mitigation with a focused native test plus separate full wasm, wasm-gc, JavaScript, and native runs; repeated zsh `status` readonly-variable pitfalls; failed-runtime-yet-edited turns; repeated API-misuse/compiler-feedback loops; bounded eight-turn inner services despite an unbounded outer goal; partial or no-tools turns; wrong `moon ide` paths and invalid `--loc`; stale `.mbti`; API/test drift; invented `Package.read` corrected to `Package.part`; an accidental Python-writer policy violation; completion narratives that did not match source; broad turns that only updated in-progress notes or changed types without migrating callers; wrong labeled-constructor patterns, invalid matches, and invalid boolean syntax; `inspect` requiring `Show` where only `Debug` existed; skipped requested edits that required fresh micro-sessions; a transient unused `mut`; and a failed runtime turn that nevertheless left valid source edits, detected by controller diff review and independent gates.

Mitigation is small, sole-author MoonCode slices: wait for `runtime_service_running=false`, inspect source and diff, then independently run `moon info`, `moon fmt`, the `moon check --target all` warning/check gate, then separate full test commands for wasm, wasm-gc, js, and native plus direct focused regressions because aggregate all missed a failure, and final diff checks. The final independent audit caught both the public-field ownership leak and the identical-XLSX format bypass before commit; separate source/test/doc repair plus re-audit was used. Requested omissions receive a fresh bounded micro-session rather than being hidden by a completion narrative.

## Audited hidden-edit loss correction

`commit_candidate` formerly decided whether to commit by scene equality. That discarded a real DOCX package edit when a `w:t` changed inside a viewer-ignored top-level `w:sdt`: the rendered scene stayed equal although the package changed. It now commits whenever the candidate `Package` differs. XLSX preserves semantic no-ops with an operation-specific, exact precheck against the existing Text-cell value. The regression test changes that hidden DOCX text, verifies the revision/dirty transition, saves, and proves the changed package content survives.

Isolation evidence is deliberately narrow: nested-mutation proof covers representative XLSX cells, diagnostics, and `VerifiedDocumentCopy::bytes()`, not every nested shape. Failed-edit byte-equality proof is likewise limited to the tested formula-cell prevalidation failure. Exact unknown-part save preservation is currently demonstrated with DOCX; shared save verification executes for all formats, but per-format sentinel-save tests remain future work.
